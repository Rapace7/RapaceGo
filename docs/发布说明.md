v0.1.31（2026-10-23）· 「打谱不再跳手」—— 按棋谱落一手只走一手；顺手把一批"不报错、但用着别扭"的地方全捋了一遍

## ★ 一、按棋谱打谱，落一手只走一手（这一版的主修）

- **症状**：回看到第 14 手，按棋谱记录下第 15 手 —— 棋盘**直接跳到这条线的最后一手**（45/45），还得再往回拉。
- **为什么**：上一版为了修「悔棋后重下同一手、后面那条尾巴够不着」，把落子改成了"落到手上就把整条尾巴接进来"。结果"按谱走一手"变成了"一步到谱末"。
- **现在**：落一手就停一手；后面的手按 → 或继续落子往下走，滑杆和手数列表里也都还在。**按记录走**（手已在树上）与**从中间岔出去**（开新支）都覆盖。
- **参照**：Sabaki 的做法 —— 落子只站到落下的那一手，"前进一手"是另一个显式动作（已对源码核对，不是凭印象）。

## ★ 二、打谱走到一半时，「这盘棋有多少手」不再错乱

- **全盘讲解**不再被误挡（原来会谎报"从第 16 手起就和主变不一样了"），也不会只讲走到的那半盘。
- **逐手讲解**完整存下整盘（原来走一半再保存，后半盘静默丢失，下次打开读不回来）。
- **导出棋谱**的文件名手数、"覆盖"按钮的判据都按整盘算（原来回看到第 16 手导出，文件叫"16手"、内容却是 20 手）。

## ★ 三、计时器不再把时间记到对方头上

- 有计时的对局，**回看中落一手**或**悔棋之后**，手数会跳 —— 原来计时只做一次"换边"，于是时间扣到另一方，超时判负也会判错人。
- 现在按「刚落子的是谁」认人；悔棋、切分支之后也自动对齐。

## ★ 四、打谱走一手，不再丢那一手的讲解

- 原来按记录一手一手走，每一手自带的讲解（以及胜率、解说词）会被当成"旧棋的残留"清掉。
- 现在**复用同一手不算换棋**，只在真换了棋时才清。

## ★ 五、几处「看着能点、其实不能」的地方

- 回看时「悔棋」「停一手」直接**变灰并写明原因**（不再点下去才被拒）；Ctrl+Z 也会说清为什么。
- **打开棋谱 / 新建对局**时，当前这盘还没导出就先问一句。
- 点到**已经有子**的交叉点给一句提示（原来毫无反应）。
- **悔棋**会把讲解和胜率收好 —— 按 → 走回去立刻能看见，不用重算。

## ★ 六、零碎

- 导入棋谱不再强制要求 `GM[1]`（省略它的合法 SGF 原来被判"不像 SGF"）。
- 修掉两处注释乱码、一个还写着早已删掉的空格键的按钮提示。
- 帮助里「回看点落子」补了两句：落一手只走一手；记录里已有的手会沿那条线走。

## ★ 七、怎么验的

- 每条都**先在真界面上复现毛病**，再改、再断言；其中"讲解被清"那条把修法临时改回旧写法跑了一次，确认断言当场变红。
- 新增/更新三套回归（落子语义 17 / 审查修复 16 / 复审追加 12）；既有分支 83、树面板 48、树布局 21、真实 217 手谱 20、试下 29 等全部重跑；随机操作 2000 步 **0 违规**。

## ★ 修：一手合法的「扑之后反提」被当成打劫，点不进去

**症状**（在别的软件对弈、在这边录入棋谱时踩到）：第 84 手白扑、第 85 手黑提掉这一子，
第 86 手白点回原处**本该提走 7 颗黑子**，软件却提示「打劫：此处暂时不能下」。

**根因**：判断「这一点是不是打劫禁着点」时**只比了坐标**（这一点是不是上一手的提子点），
没算「这一手本身也只提 1 子」。倒扑这手一下提 7 子、局面根本不会重复，却被前一道闸门拦住。

**修法**：劫的判据换成主流开源围棋软件 **Sabaki** 的写法（四条同时成立才算制造劫）：
本手只提 1 子 · 落下的这子是**孤子** · 它只有 1 口气 · 那口气正是刚被提掉的那一点。
「孤子」这条正是倒扑的抗体 —— 提完还连着己方大块的，一律不是劫。

顺带修掉一个同源的隐患：悔棋 / 切分支后重算禁着点时，**盘面和手数会错开一手**，
算出来的是另一个局面的禁着点。现在两者一一对应。

## ★ 修：点分支树里的珠子之后，棋盘上的落子预览小方块没了

**根因**：预览方块原来有条限制「只在看到最新一手时才画」。
点树上的珠子 = 跳到那一手 = 进入回看 → 预览就被挡掉了，看着像坏了。

看上去就是线从珠子背后穿过（不是插进珠子里）。放大 3 倍实拍确认过，不是事故。

## ★ 默认收起、按需展开；「全部收起」留着

树面板默认只画主变，角标上写 `+3` 就表示那一手有 3 条侧支 —— **点角标才展开**。
工具条上加了「**全部收起**」（一键回到只看主变）。「全部展开」**已删掉**。

## ★ 修「树最上面拉不上去」

以前树短的时候会**纵向居中**，于是内容上溢到滚动区上方、**那段永远够不到**（顶部被吃掉）。
现在一律**顶部对齐**，长树短树都不会再出现。

已经讲过几手、还剩几手。取消随时可以点。

## ★ 手数分支树（这一版的大功能）

以前这软件只有**一条**手顺线：回看某一手时想试试别的下法，只能「试下」打个草稿，一退出就没了，
棋谱也存不下来。

现在能**真正开分支**了：

| 你想做的事 | 怎么做 |
|---|---|
| 在某一手试试别的下法 | 把局面退到那一手，**直接落子** —— 自动开一条新分支，原来那条线**留着不丢** |
| 在分支之间来回看 | `↑` `↓` |
| 把某条分支变成主线 | 跳到那一手，按 **PgUp**（原主线整枝还在，随时切回去） |
| 删掉一整条分支 | 按 **Delete** —— 会先问一次，再按一次才真删；**删错了按 `Ctrl+Shift+Z` 撤销** |
| 一眼看全所有分支 | 手数卡右上角的滑杆切到「**树**」 |
| 分支存进棋谱 | 导出时自动写成标准变着 `(旧线)(新线)`，别的围棋软件也认 |
| 打开带变着的棋谱 | 直接能看、能切分支；手数列表里标 `⑂1/2` |

**树面板长什么样**（参照 KaTrain 的「珍珠手串」）：

- 黑白棋子连着串起来，**主变那条串金色外圈**，当前在看的那一手是**青色环 + 放大**；
- 旁支从母珠上**分出一条线垂下来**再接进去，行与行之间不会交叉；
- 鼠标**悬停**出详情：手数 · 黑白 + 坐标 · 这一点共几种走法 · 这一手亏/赚多少胜率 ·
  复盘目损 · 此时黑棋胜率 · 有没有讲解；
- **右键按住拖动 = 拖动画布**（原地右击才弹菜单：提升主变 / 删除分支）；
- 珠子上的手数是「**12a 式**」：分岔后同一支上的手共用字母后缀（12a、13a…），主线不带后缀。

**试下（打草稿）不进分支树** —— 它还是「临时摆摆」，退出就干净了，不会在树上留幽灵旁支。

## 起因：一条讲解 bug，牵出了整块重写

用户实测发现：**黑棋第 5 手实际下在 D16，讲解却在讲「如果黑棋下在 D4……」** ——
整段讲的是另一个点。查下去发现不是一个小错，是**讲解的输入给错了**。

**根因**：讲解一直拿「这一手**之前**」的盘面交给模型，却要求它讲「这一手**之后**」。
在那个盘面上**正好轮到刚落子的那一方走** —— 模型看到的是「该我选点了」，
于是本能地退回它最擅长的「列候选点」。D4 就是它列的候选之一。

（顺带排除过一个更可疑的方向：**不是坐标系上下颠倒**。专门测过 ——
给模型一颗子问「它下在哪」，放 D16 答 D16、放 Q16 答「右上角」、放 C4 答「左下角」，全对。）

## 一、讲解现在长这样

每一手按 **结论 → 道理 → 对照** 三段给：

| 段 | 内容 | 谁说了算 |
|---|---|---|
| **① 结论** | 好棋就夸、烂棋就骂（口语，不写棋评八股） | **KataGo** 的胜率涨跌 |
| **② 道理** | 这一手碰到了谁、对方大概怎么应、好在哪差在哪 | LoGos 讲 |
| **③ 对照** | AI 当时更倾向下哪儿、那手多少胜率、你这一手差了几个点 | **KataGo** 给的数字 |

**好坏一定由 KataGo 说了算，不让模型自己判断。** 为什么：实测同一手亏 8.5% 的棋跑两次，
模型一次骂「不太像棋啊」，一次夸「碰得很有想法」—— 它不稳定，而且会**自己编胜率**
（写出过「这个变化下白棋胜率 71.4%」这种根本没算过的数）。
现在结论由程序写死、模型只负责顺着讲理由。

## 一之二、讲解不再「瞎编盘面」（本次最重要的一处）

有用户实测发现：某手落在**空空如也的角上**，讲解却说「这手**碰**得有点早」
「黑棋在**四个角**都有子力，白棋的布局明显落后了」—— **全是编的**。

**根因**：一直是让模型**自己去读那个 19×19 的数字矩阵**，判断"这一手碰到了谁"。
7B 读不准，读不准就凭"棋局感"瞎编。

现在**盘面事实全部由程序算好喂进去**，模型只负责顺着事实讲道理：

- **挨着谁** —— 四周八格没子，就明说「它既不是碰、也没挨着谁」
- **什么位置** —— 星位（4-4）/ 小目（3-4）/ 三三（3-3）/ 边 / 中腹
  （实测它把 3-4 的 D3 说成过「星位」）
- **四个角各有几颗子** —— 免得它再说"四个角都有子"

并且加了一条**硬规矩**：事实说是空的，就**不许写「碰」「靠」「挡」「断」**。
（光把"它不是碰"写在事实里没用 —— 它照样无视；写成一条独立规矩才管住。）

同一手、同一局面，改前改后：

| | 输出 |
|---|---|
| 改前 | 「白棋这手 **D3 碰**，明显是针对黑棋在左上小目的布局」 |
| 改后 | 「白棋在**左下小目（3-4）落子**，这个位置太偏了，既不能有效占角，对黑棋的压迫也不够。黑棋完全可以不理它」 |

> **还治不好的**（7B 的能力边界，如实说明）：更细的地方它仍会编 ——
> 比如事实里写了「左上 黑1白2」，它照样说「黑棋左上**两子**」。
> 所以：**事实类的信息（坐标/胜负/目损/碰到谁/什么位置）一律由程序给，
> 一个字都不让模型猜；棋理类的分析交给模型，但别指望它精确。**

## 二、顺手清掉的六类废话

跑完整盘 217 手**逐手看**，模型翻来覆去就这几种毛病（下面每条都是真实原句）：

- **动作旁白**：八十多手出现「（对着棋盘沉思片刻）」「（轻笑着摇头）」「（自言自语：…）」
  「（用教学语气）」—— 它把讲解写成剧本了
- **自己编的胜率**：一律删；要数字由程序在最后补真的
- **推演变化图**：「如果选择 D11 粘，预计变化：粘 / 扳 / 扳 / 粘……」这种残渣
- **替对方支招**：「现在白棋有几个不错的选点值得考虑：」「白棋现在可以下在 P5 粘住」——
  你问的是这一手怎么样，不是教对手下棋
- **数字分点罗列**：「1. 白棋下在 J18 粘住」—— 同上，而且把讲解写成条目了
- **「我建议…」**：「我建议黑棋立即在 B17 扳一手」—— 评论员不该替谁出主意

### 顺带修掉的一个真 bug：讲解里出现「7一带」

有用户截图报的：某几手讲解里冒出「**7一带**已经形成了相当厚实的外势」，完全看不懂。

查出来是**我们的清理正则干的** —— 模型用训练数据的记谱法写「X-L17」/「O-L17」，
而我们的清理是**把整段抹成空格**（当初的理由是"用户看不懂一个字母加横杠接坐标"），
于是「黑棋在 X-L17 一带」变成「黑棋在  一带」，甚至「X-L1 7一带」变成「7一带」。

现在改成**只去掉前缀**：「X-L17」→「**L17**」。
—— 用户当初抱怨的只是**那个格式**看不懂，坐标本身是该留的。

## 二之二、每手要讲「两三句」，不是只给一句结论

第一轮整盘跑完发现：有些手只剩「这手不行，这手有问题啊。」—— **只有结论，
没有理由，也没说这样下会怎样**。

查出来是两层：① 给模型的生成长度太小（340），它写到 460 字左右就被**掐断**，
原始输出结尾是「这个变化虽然也能吃掉黑」这种半句；② "太短也算合格"的门槛太低，
这种一句结论也被放行了。

现在：生成长度 **340 → 520**、"讲出东西"的门槛 **40 字 → 70 字**
（不合格就重讲一遍），并在提示里把**必须说到的三点**写死：
碰到谁 / 对方大概怎么应 / 为什么好或不好。

## 三、棋手名能存进棋谱了

**原来**：打谱时点名字改名，界面上变了、**文件里没变**，重开还是 `PLAYER1` / `PLAYER2`，
改几次都白改。原因：改名只写进了内存，而唯一会落盘的那条路只在「下完棋点保存」时才走 ——
打谱时根本不会触发。

**现在**：改完**立刻写进棋谱**（SGF 的 `PB` / `PW` 两项），别的软件也认。
而且**只改这两个字段** —— 棋谱里的备注、解说词一字不动。

  替换它原来的内容 —— 改完棋谱不用再「另存成一份新的、再手动删旧的」。
  覆盖前会自动留一份 `.bak` 备份，能捞回来。

每手胜率（胜率 / 目差 / 目损）**一直存在复盘报告里**，但打开棋谱时**不读它** ——

数据本来就在，只是没人去拿。

现在**打开棋谱就自动带出来**：涨跌列有数字、走势图有曲线，不用再算一遍。

## macOS 版：能用，但你要自己打包

代码层面已经支持 macOS 了。但**我们不提供预编译的 Mac 包** —— 原因很实在：
**开发者没有 Mac 机器**，打出来的包没人能实测，不敢发没验过的东西；
而且 Apple 的签名公证要开发者年费（$99/年），暂时没投。

不过 **"自己打包"只需要四条命令**，而且 Mac 上装引擎比 Windows 还简单：

```bash
brew install katago                    # Metal 后端，Apple Silicon 原生
git clone https://github.com/Rapace7/RapaceGo.git && cd RapaceGo
npm install && npm run dist:mac        # 产出 dist/RapaceGo-mac-arm64.zip
xattr -cr /Applications/RapaceGo.app   # 未签名包第一次打开要过 Gatekeeper
```

**那 Releases 里的 `RapaceGo-mac-*.zip` 是什么？** 是我在 GitHub 的 macOS 机器上
打出来的**参考产物** —— 给不想自己装 Node 环境的人直接用。同样是**未签名**的，
第一次打开照样要 `xattr -cr` 或右键→打开。

**已知限制（诚实说明）**：
- **只承诺 Apple Silicon（M 系列）** —— Homebrew 有 arm64 预编译瓶；
  Intel Mac 没有瓶，`brew install katago` 会从源码编译，很久。
- **整条 Mac 路径没有实机验证过**（没有 Mac 机器）。代码改动是完整的
  （引擎名不再写死 `.exe`、加了 Mac 应用菜单、⌘ 快捷键），
  在 Windows 上跑全套测试确认没改坏，但**真机效果要靠反馈**。

## 实现里踩到的两个坑（都记在代码注释里了）

**坑一：CSS 的 `scroll-behavior: smooth` 会和"先归零再测量"打架。**
它让**每一次** `scrollTop` 赋值都变成动画 —— 于是"把滚动归零、再量目标元素的绝对位置"
这套算法失效：赋值后立刻量，量到的还是动画中途的值（实测设了 `0`、读到 `72`），跳转位置全错。
**去掉 CSS 的平滑滚动，改成自己在 JS 里用 rAF 做** —— 该瞬时就瞬时、该平滑才平滑。

**坑二：在布局不稳定的时候量位置。**
弹窗关闭时是 `display:none`（里面所有元素位置都是 0）；
刚打开时还在做出现动画（量出来会偏）。两次都栽在同一个病上。
现在改成：**只在弹窗稳定显示后量一次、缓存起来**，之后所有跳转都用缓存值，
不再依赖任何实时测量。

## 修的问题（我自己在 v0.1.21 里引入的）

做 v0.1.21 的权重自动识别时，我把"失效就回退"加在了 `normalizeConfig` 里 ——
而那个函数的结果会被 `settings:save` **写进 settings.json**。
于是实测发现包里存下了：

```json
"analyzeWeight": "...\\RapaceGo懒人包\\KataGo\\weights\\Bot.bin"   ← 自动识别结果，不是用户填的
```

**这恰恰破坏了我们自己的设计**：一旦用户把文件夹挪个位置 / 复制给别人，
这两条就变成失效的绝对路径，而那本来是"相对软件目录解析"就能解决的问题。

## 改法：把"解析"和"存盘"分开

| 环节 | 该做什么 |
|---|---|
| `readConfig`（读盘） | **做失效回退** —— 路径指的文件不在了就退回默认（运行时决定"用哪条"） |
| `normalizeConfig`（存盘用） | **只做"填了没有"的规范化，不解析** —— 用户填什么就原样留着 |
| `settings:save` | **与默认值相同的路径不写进配置文件**（含「最近用过」列表） |

判据很直白：**结果等于默认 → 就等于"没有自定义" → 不必存**。
存下来的只可能是"用户确实指到了别处"，那才该持久化。

v0.1.21：支持裸 `.bin` 权重（夸克网盘那种：解压后的文件）

## 修的问题

用户报：**夸克网盘不允许分享压缩包格式**，所以把 KataGo 权重 `.bin.gz` 解压成 `.bin`
再上传，别人下到 `.bin` 之后，在「设置」里**选不中那个文件** —— 手里明明有权重却用不了。

**根因**：我们把后缀和文件名都写死了。一共**四处**：

| 地方 | 原来 | 现在 |
|---|---|---|
| 文件选择框的过滤器 | `extensions: ['gz']` | `['gz', 'bin']` + 一个「全部文件」兜底 |
| 自动扫描权重（`guessWeights`） | 只匹配 `\.bin\.gz$` | `\.bin(\.gz)?$` —— 两种都认 |
| 选错文件时的报错文案 | "请选 .bin.gz 结尾的权重" | 说明两种都行 |
| **默认权重路径**（`defaultPaths`） | 把文件名**写死**成 `b11c768nbt.bin.gz` / `b18c384nbt-humanv0.bin.gz` | 找不到就在**同目录**里找同类权重 |

**最后那条才是致命的**：懒人包里放的是**解压后又改过名**的裸权重（`Bot.bin` / `Human.bin`），
跟写死的名字对不上 → **双击懒人包后两个权重路径全指空、引擎起不来**，
而用户去设置里手动选时文件框又只显示 `.gz` → **开箱不能用**。

**还补了一道**：`normalizeConfig` 里，如果配置中存着的路径**已经失效**
（挪过文件夹、或之前手动选过旧文件），也去同目录找同类权重 ——
否则光是"从没配过"的人能得救，**配过的人反而永远卡在「★ 找不到」**。

**KataGo 本身完全支持裸 `.bin`** —— 实测：解压出的 268 MB `.bin` 能正常加载、分析、
返回候选点与胜率，与 `.gz` 行为一致（只是文件大一点：约 200 MB → 约 270 MB）。

**认名字的规则**：带 `human` 字样的归**对弈**权重、其余归**分析**权重，**大小写无关**
（所以 `Human.bin`、`human.bin`、`Bot.bin`、`bot.bin` 都能自动认）。

## 更新到这一版要替换什么

**不用重下整包**（懒人包 8GB 里 8GB 都是引擎和模型，它们没变）。
只要替换 `resources\app\` 里的文件即可 —— 从 GitHub 下的那个 `RapaceGo.zip`（约 146 MB）
解出来，把里面的 `resources\app\` 覆盖到原来的位置：

```powershell
Expand-Archive RapaceGo.zip -DestinationPath $env:TEMP\rg -Force
Copy-Item "$env:TEMP\rg\resources\app\*" "你的懒人包\resources\app\" -Recurse -Force
```

> ⚠️ **只覆盖 `RapaceGo.exe` 是没用的** —— 它只是 Electron 的启动壳，**不含程序逻辑**；
> 真正的代码在 `resources\app\main.js` 和 `resources\app\renderer\` 里。

v0.1.20：规则全面审查（对照 KataGo）+ 采纳外部贡献 + 推荐落点交互澄清

## 一、规则审查：揪出并修掉三个规则错误

这一版把围棋规则对着**权威实现**逐条核了一遍（KataGo 的规则引擎 + 开源围棋软件 KaTrain）。

**① 让 3 子的位置错了。** 第三子原来摆在**左上**，通行摆法是**右上**。
（KataGo 的 `place_free_handicap 3` 输出 `D4 Q16 Q4` 可印证。）2/4~9 子都是对的，只有 3 子这一档错。

**② 座子制（明清规则）的黑白放反了。** 原来是「左上/右下 = 黑」，
正确是「**黑子在右上角 + 左下角，白子在左上角 + 右下角**」
（依据：座子制通行规则原文「黑座子放置于右上角和左下角的四四位，白座子依此类推」）。
这个错影响整套明清规则 —— 古谱摆出来黑白是反的。

## 一、修「推荐点永远不出来 / 那行『计算中… N』定住不动」

**根因**：悔棋时会清掉"这批选点作废"的记号，但**另一个记号没跟着清**。

```js
if (state.candAt > len) state.candAt = -1;   // 这批选点废了
if (shownAt > len) shownAt = -1;             // ← 只管了"大于新长度"这一种情况
```

悔棋**退到某一手**时会出现：`candAt`（比如 6）> `len`（2）→ 清成 -1；
但 `shownAt` 恰好**等于 2**（≤ len）→ **原样留着**。

于是**「这批选点废了」与「这个局面显示过了」同时成立**，成了死结：

- `runAnalysis` 判 `shownAt !== cur` → 为假 → **跳过当前局面，不重算**
- `scheduleAnalysis` 又因 `history[cur]` 有值 → **不入队**

两头都不动手 → **那个局面永远不再分析**。修法：这两个记号是同一批结果的一对，
**要废一起废**。

**怎么找到的**：前两版都没修对（我先判成"记在了没上屏的结果上"——那条本身对，
但没打到这个问题；我加的自愈网还被自己写坏、只试一次就放弃）。
最后是让它**把分析链路的关键决定写进日志文件**，从日志里直接看到：

```

★ run 认为已算过但 candAt=-1 ≠ viewAt=2
```

## 怎么找到的（这次不是猜的）

用户报「AI 落子后很短时间内点悔棋，选点推荐和形势分析就卡住不显示，有时候会有时候不会」。
我在两台机器上做了三轮压力测试（共 100 轮、含 AI 思考中悔棋、悔棋延迟随机 0~400ms），
**一次都复现不出来**。

于是给软件加了一个自检键（Ctrl+Shift+D），让用户在自己那台出问题的机器上按一下。
他读出来这一行：

```
分析自检·局面: 2手·看第2手·选点: 还没算过·搜索量: 200·请求: 空闲·引擎: 就绪·链路: 轮30/成功19/空跑0
```

**这一行就把病灶锁定了**：

| 读数 | 说明 |
|---|---|
| `选点: 还没算过` | `candAt = -1`，候选点从未上屏 |
| `搜索量: 200` | **请求发出去过、也回过进度**（所以不是"没发请求"） |
| `请求: 空闲`、`空跑0` | 队列空了、没有待办、也没有请求失败 |

三个事实合起来只有一个解释：**软件认为「这个局面已经算过了」，所以永远不再算它。**

## 真根因（一行代码）

```js
applyAnalysis(res, at);   // ← 内部有提前 return（报文与当前局面不符 / 搜索量太低时直接返回）
shownAt = at;             // ← 但它**无条件**标记"已上屏"
```

`applyAnalysis` 提前返回时候选点**根本没画上去**，可 `shownAt` 已经记成"这个局面显示过了"。
而 `runAnalysis` 的判据是 `shownAt !== cur` —— 于是这个局面**永远不再重算**：
棋盘上方那行「计算中… N」定住，推荐点永远不出现。

**为什么"有时候会有时候不会"**：`at !== state.viewAt` 那条判断 ——
**报文回来时局面刚好又变了**（AI 刚落子、或用户刚落子），这一趟结果被当成
"补历史欠账"处理：只记走势、不画选点。这是个竞态，只在特定时序成立，所以偶发。

## 修法

1. `applyAnalysis` 现在**如实报告**有没有真上屏（返回布尔）：
   报文与当前局面不符 → false；搜索量太低（<20）→ false；真画上去了 → true。
2. `runAnalysisOnce` **只有真上屏才记 `shownAt`** —— 没上屏就留着重算，死结解开。
3. 再加一道**自愈网**：若出现「算过但没上屏」这个不一致状态（`shownAt === viewAt`
   但 `candAt !== viewAt`），6 秒后自己重算一次。万一还有别的路径造成同样不一致，
   也不会再卡住等用户"再落一手"来撞开。
4. `Ctrl+Shift+D` 自检键修好了（原来写在 `switch` 里，被上面一道 Ctrl 总闸提前 return
   挡成死代码，按了没反应）+ 加了分析链路计数。

|---|---|
| `applyAnalysis` 四种入参的返回值 | 正常→true / 局面不符→false / 搜索量太低→false / 空结果→false ✅ |
| 人为造出用户那个卡住状态，自愈网 | **6 秒救回**，候选点上屏，路径记进埋点 ✅ |
| 强制重算后 `shownAt` 与 `candAt` 一致 | ✅ |
| 综合回归（悔棋/回看/涨跌/刷新/一致性） | 全绿 ✅ |
| 打劫回归（悔棋×打劫，用那份 GN[打劫BUG] 棋谱） | 全绿 ✅ |

| 极限压力 40 轮（独立调试实例、rank_3d、极短延迟悔棋） | 恢复 1.3~1.5 秒，无卡住 ✅ |

   > This neural net requires a newer KataGo version. Obtain a newer KataGo at https://github.com/...

## 现象

**一、涨跌数字会变。** 下完一手，手数列表里那一手右边显示一个数字（比如「−2.4%」），
过一会儿再点回去看，变成另一个数（比如「−16.8%」）—— 原本算是亏的，再看看就不亏了。

**二、引擎像是卡住了。** 偶尔出现：棋盘上推荐选点不出来，棋盘上方那行「**计算中… 320**」
定在一个数字上不动，点悔棋、回看、落子都没反应，只能重启软件。

## 根因

### 一、同一手被算了十几遍

引擎每 0.25 秒推一次「算到一半」的中间报告，**每一份都往走势数据里写一次**，
而列表读的是最后一次写的值。实测（连落 6 手）：

| 同一手 | 被写了几次 | 各次搜索量 | 胜率极差 |
|---|---|---|---|
| 第 1 手 | 6 次 | 151 / 298 / 463 / 515 / 515 / 515 | 0.62% |
| 第 4 手 | 4 次 | 152 / 312 / 471 / 514 | 1.63% |
| 第 5 手 | 5 次 | 168 / 340 / 515 / 515 / 515 | 1.69% |
| 第 6 手 | **14 次** | 165 / 326 / 480 / 514 / 515 … | **8.06%** |

第 6 手那一行就是您看到的现象：27.7% → 19.7% → 32.9%，来回跳。
**不是"算得太短"，是"算了十几遍、而且用最早那份粗算覆盖了收敛后的结果"。**

### 二、分析请求有一条"回不来"的路

分析链路上每发一次请求都要等引擎回话。万一那一次等待**永远不返回**，
「一次只允许一个分析在跑」那道闸门就永远占着 → 整个分析停摆：
选点不刷新、胜率条冻住、那行「计算中… N」定住不动 —— 三条现象同时成立。

## 修法

**一、涨跌数字改成「算准了才出现，出现后不再变」**

- 搜索量不到「计算深度」90% 的结果，**只允许填空、不许覆盖已记的数据**；
- 达标的结果才允许覆盖，而且不许用更少搜索量的结果改写更多的那一份；
- 没算准的那一格显示「**…**」（占位），算准了才变成数字。

> 试过一版「新结果比旧结果搜索量高 1.25 倍就允许覆盖」——**形同虚设**：
> 中间报告的访问量是 122 → 294 → 489 → 515 逐级涨的，每一级都比上一级高 2.4 倍，
> 于是每一级都过了那道门，数字照跳。必须用**目标值的绝对比例**当门槛。

**二、请求回不来的路，两头都兜住**

- 渲染端加 25 秒超时：超时就放弃这一次、主动重排一次（连续 3 次仍超时才停手并提示）；
- 顶栏状态灯旁边加一个「**刷新**」按钮：卡住时点一下 —— ①放开卡住的分析并重排；
  ②重新查一遍引擎真实状态；③引擎真挂了就卸载再加载（等于重启引擎）。

**三、顺手加固两处**

- 补账队列加上限（40 条）：连点几十手之后，引擎不会再长时间忙于补很久以前的数据；
- 新增 `Ctrl+Shift+D`：把分析链路的内部状态打到状态栏上（自检用，排查"点不出来"）。

## 验证

- **涨跌数字**：刚落显示「…」→ 收敛后出数字 → 之后连续采样 5~6 次**一个字都不变** ✅
- **悔棋 ×3**：选点跟上新局面耗时中位 **121ms**，队列不残留、走势数据长度正确 ✅
- **回看旧手 → 回最新 → 连悔两次 ×3**：每次都在 200ms 内收敛、零欠账、不卡 ✅
- **刷新按钮**：正常点=重算当前局面；把闸门人为卡住后点=立刻放开、清队列、恢复分析 ✅
- **补账会不会拖慢选点**（专门量过）：有欠账时选点延迟中位 **377ms**，
  无欠账 **470ms** —— 选点排在补账前面，补账**不拖慢**选点 ✅
- 顺带量到一个反直觉的：计算深度 200 / 500 / 1000 三档，**推荐点出现快慢几乎一样**
  （都在 0.49 秒）—— 因为推荐点在引擎吐出第一份结果时就画上去了。已写进帮助。

## 关于「三大目录」的分工（维护者备查，也免得自己混）

| 位置 | 是什么 | 里面该有什么 |
|---|---|---|
| `RapaceGo\`（开发目录） | 改代码、跑测试的地方 | 源码 + `node_modules` + 一堆 `_` 开头的开发脚本 |
| `dist\` | **只放要传 GitHub 的东西** | 只有 `RapaceGo.zip`（`win-unpacked` 是中间产物，同步完自动删） |
| `玄清围弈\` | **本地自用的免解压版**（唯一一个） | 可直接双击运行的完整程序 |
| 桌面 `RapaceGo懒人包\` | **给别人下载用的整包**（传网盘，**不传 GitHub**） | 程序 + KataGo + LoGos，解压即用、零配置 |

> **为什么懒人包不上 GitHub**：它 8.2 GB，而 GitHub Release 单个附件上限 **2 GB**，
> 且大头（4.4GB 的 `.gguf` 模型、296MB 的 `.bin.gz` 权重）**本身就是压缩格式**，
> 再打 zip 也压不动。GitHub 那份走轻量路线（146MB + 首次运行自动下模型）。

### ★ 懒人包的目录约定（做包时最容易搞错的一条）

`main.js` 里打包态的「引擎位置」是**和 `RapaceGo.exe` 平级**，不是上一级：

```js
BASE_DIR = IS_PACKAGED ? path.dirname(process.execPath) : __dirname;  // 打包后 = exe 目录
const up = IS_PACKAGED ? BASE_DIR : path.join(__dirname, '..');        // 打包后 up 就是 exe 目录本身
katago: path.join(up, 'KataGo', 'engine', 'katago.exe')
```

所以懒人包的布局必须是：

```
RapaceGo懒人包\
├─ RapaceGo.exe      ← 和下面两个目录平级
├─ KataGo\engine\katago.exe + weights\
└─ LoGos\llama-server.exe + *.gguf
```

**别把程序本体再套一层 `RapaceGo\`** —— 那样软件会去找 `懒人包\RapaceGo\KataGo\...`，
而文件在 `懒人包\KataGo\...`，结果引擎永远起不来（实测 `settings.check` 五项全 false）。

重建懒人包：`powershell -File _build_lazy.ps1`（已含"删掉 settings.json / records"等铁律）。
